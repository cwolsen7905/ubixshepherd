# uBixShepherd 0.6.0-beta.1

Release notes for the tag cut on 2026-10-23. The changelog section for this
version is what the release workflow publishes; this page is the longer form.

This beta follows 0.5.0-beta.2. The largest changes: keep-going mode now starts approved
work itself, Crook keeps a log of every verdict you can query, a new upkeep pass (Muster)
tidies stale lists, lanes can set approved check files aside, and merge rules can run in
shadow mode. Nothing is removed and no existing use breaks. New config keys and a few new
routes, commands and tools are additive.

## What's new

### Keep-going mode starts approved work itself

- With keep-going on, the daemon continues approved items whose lane never ran or whose
  last run a crash interrupted, then starts approved items with no lane, in rank order,
  until the run slots are full. Nothing depends on a client being attached or on the desk
  choosing to act.
- A new lane takes the scope named by its item's plan document (a line such as
  `Scope: internal/x/**, docs/y.md`). An item whose plan names no scope is held and the
  feed says so. An item with neither a plan document nor an acceptance line is held too.
- Every start passes the same gate as the desk's: the spend cap, run cap, idle time, end of
  day and starts per lane still hold, with the reason in the feed. A refused start closes
  the lane again and unlinks the item, so no idle lane holds the repo.
- `shepherd keep-going status` ends with a summary of what the mode did since it was
  turned on: items started, runs finished and failed, merge requests, and why and when it
  stopped. The stall alert lists each item with its own blockers.
- The drive never answers a decision, approves, merges, pushes for a person, tags,
  releases or deploys. See [keep-going.md](../keep-going.md).

### Crook keeps a verdict log

- Every answer to "may Shepherd do this now?" that a call site acts on is written to the
  daemon's store with the rule that decided, its stage, the actor and a redacted reason.
- `shepherd crook why <id>`, `why run <id>` and `why lane <name>` explain a past hold or
  refusal; `crook log` and `crook rules` list and count verdicts. All take `--json`.
- Crook also loads rule files and layers, and evaluates them against shared test cases.
  See [crook-why.md](../crook-why.md).

### Muster: the upkeep pass

- A plain-code pass on the watcher's tick looks over artifacts, lanes, runs, next-up items,
  questions and decisions for what has gone stale. It tidies what is safe and can be
  undone, and raises a finding, with a one-click fix where there is one, for the rest.
- Every finding and fix is a row in the muster log, and an applied fix can be undone for
  a number of days. See [muster.md](../muster.md), which also says what is not built yet:
  the routes, CLI and web screens that show and act on findings.

### Checks first: approved check files

- Lanes can set approved check files apart. The files are recorded when the person
  approves them with `checks.approve`, left out of a build lane's scope, and released
  with `checks.release`. Both are the person's actions in Crook.
- Opening, rescoping, pushing and shipping a lane respect the set, and `lane ship`
  refuses a branch that changes approved check files.
- The daemon serves `/v1/checks`, lane views list excluded files, and approving or
  releasing checks appears in the feed.

### Merge rules in shadow mode

- A repo can have a merge rule in `.shepherd/rules/<id>.md`. In shadow mode Shepherd works
  out what the rule would have done for each open lane merge request and records it.
  The person still merges, and shadow mode never merges, approves, retries a job or posts.
- `shepherd crook shadow [--rule R] [--since 14d] [--limit N]` lists the records (also the
  `crook_shadow` MCP tool), and `crook rules` counts shadow rows apart from real
  decisions. See [merge-rules.md](../merge-rules.md).
- The daemon's forge watcher runs the pass for each open lane merge request, apart from
  the poll, and records an outcome row when the person merges. A failed pass records
  nothing. Going live is not built yet.

### Follow-through by an external owner

- A repo can name another service as the owner of a merge request's failed pipelines and
  review threads. Shepherd stands back, and takes an item over if the owner stays silent
  past `patience` (or says `Unfixed:`). See the Follow-through owner section of
  [config.md](../config.md).

### Follow-through escalates to Claude

- When a round on a merge request's failed pipeline or review threads does not close what
  it was sent to close, the next round runs on Claude Code instead of the agent that took
  the first one. The first round is never escalated. See [follow-through.md](../follow-through.md).

### Web UI

- One error, loading and empty state across the views, with a working Retry on the reads
  that can reload and a back link on the error state.
- The side panel has panes for a routing request and a next-up item.
- The Forge watcher card on the daemon status page names the forges the watcher can read
  and how often it polls, or says polling is off.

## Changes

- `shepherd next list` filters by repo, topic, state and text (`--topic` matches a
  conversation topic and refuses an ambiguous title), and fetches dropped and done items
  when `--state` asks for them.
- The desk's `run_stop` tool takes `for_restart`, which hurries a drain. A run stopped that
  way is continued after the restart, and the CLI says when `--for-restart` is used with
  no drain under way and falls back to a plain stop.
- Agents are told in every brief never to skip git hooks. Claude Code runs deny
  `--no-verify`, `commit -n` and `core.hooksPath` overrides by pattern, and Copilot runs
  deny them where they follow the subcommand. The pre-push hook no longer suggests
  `git push --no-verify` to an agent's run, and a run seen skipping hooks is flagged once
  in the feed. These are cooperative guards, not a boundary.
- Approving and releasing checks, and lane rescoping, fail closed on lookup and git
  errors; feed text for check approvals and releases is redacted.
- The forge reader looks for the renamed AI review job when it retries an approval.
- Documentation: merging follows each repo's merge rule.
- `make check` runs the web checks as well as the Go checks.

## Fixes

- An answer to a decision whose asking run was superseded continues the lane's latest
  run's session instead of reviving the old conversation.
- A thread reply to a desk question now closes it, in order with skips and answers.
- Crook's log writes verdicts in the background, logs an identical hold or refusal at most
  once a minute, and ends a path at its stage. Rule loading refuses class matchers where
  classes are unknown, folds case in the rules-folder floor, and skips symlinked rule
  files and folders.
- Keep-going: a lane whose item link failed is taken up, a start counts only after the run
  starts, drive lanes are scoped by plan, and refused starts close their lane.
- Artifacts: declared screenshots over 10 MiB survive a lane closing, the no-copy feed line
  is written only after a close succeeds and is worded neutrally.
- Muster: the pass asks about a running run with no pid, keeps a decision whose run cannot
  be read, clears findings only for checks that finished, and leaves artifacts alone when
  the worktree is missing. Scope offers need a widening verb and safe paths.
- Rescope works for a repo whose directory is gone, and returns the error when the repo's
  files cannot be listed.
- Merge-rule shadow reads say when they hit the row cap and count `merged_after` for any
  verdict; a shadow row whose write failed is retried, with one feed line per head.
- Follow-through: an owner's `Unfixed:` thread is taken at once on first sight, and the
  authors clear when a repo returns to `shepherd`.

## Upgrade notes

- **No breaking changes.** Existing config files, CLI use, routes and MCP tools keep
  working.
- The store gains new tables (the Crook verdict log, the Muster log and the approved check
  files) as forward-only migrations applied when the new daemon starts. An older binary
  refuses a store migrated by a newer one, so going back a version can mean a fresh store.
- Upgrade with the update notice (**Upgrade** in the web UI, `shepherd update upgrade`, or
  `/update upgrade` in `shepherd chat`), or rerun the install script. Restart the daemon
  so agents drain and continue. See [INSTALL.md](../INSTALL.md#upgrade).
- Minimum git is still 2.31.

## Config keys and interfaces added

| Where | Addition |
|---|---|
| `config.yaml` | `muster:` section with `stale_days` (3, 0 turns the check off), `batch_days` (3), `digest_days` (3), `skip_days` (7) and `undo_days` (7); negative values are refused |
| `defaults:` or a repo's `watch:` | `follow_through:` with `owner` (`shepherd` or `external`), `name`, `patience` (30m) and `author` (required with `owner: external`) |
| Rule files | `.shepherd/rules/<id>.md` with `kind: merge`, `mode: shadow` and `require:` conditions |
| HTTP API | `/v1/checks`, `/v1/crook/verdicts`, `/v1/crook/rules` |
| CLI | `shepherd crook why`, `crook log`, `crook rules`, `crook shadow`; `shepherd next list` filters |
| MCP tools | `crook_why`, `crook_shadow`; `run_stop` gains `for_restart` |
| Feed | kinds `checks_approved` and `checks_released` |

## Known limits

- Muster has no routes, CLI or web screens for its findings yet.
- Merge rules cannot go live: there is no forge merge call, revert or switch yet.
- The git-hook guards for agents are cooperative, not a boundary.
